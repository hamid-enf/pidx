# ۱۱ — Feedforward

## ایده

PID **واکنشی** است: تا خطایی نبیند کاری نمی‌کند. Feedforward **پیش‌دستانه**
است: اگر می‌دانید برای رسیدن به یک setpoint چقدر خروجی لازم است، چرا صبر
کنید تا خطا انباشته شود؟

$$u = \underbrace{u_{\text{FF}}}_{\text{از دانش شما}} + \underbrace{u_{\text{PID}}}_{\text{تصحیح باقیمانده}}$$

## دو شکل استفاده

### مقدار ثابت

```c
PID_SetFeedforward(&pid, 0.5f);   /* افزوده می‌شود به خروجی */
```

مفید وقتی نقطهٔ کار مشخصی دارید (مثلاً جبران گرانش در یک بازوی رباتیک).

### تابع

```c
static PID_Float my_ff(PID_Float setpoint, PID_Float measurement, void *ctx)
{
    (void)measurement; (void)ctx;
    return setpoint / PROCESS_GAIN;   /* مدل معکوس ساده */
}

PID_SetFeedforwardFn(&pid, my_ff, NULL, 1.0f);   /* fn, ctx, gain */
```

هر نمونه صدا زده می‌شود. باید سریع و بدون مسدودشدن باشد.

## اندازه‌گیری‌شده

از `examples/08_freertos_task` — IAE گذرا:

یعنی **۳۶٪** بهبود با یک مدل معکوس یک‌خطی.

## نکتهٔ مهم: FF خطای ماندگار نمی‌سازد

چون انتگرال‌گر باقیماندهٔ FF ناقص را جمع می‌کند. اگر FF شما ۸۰٪ درست باشد،
انتگرال ۲۰٪ باقی را می‌گیرد. پس **FF تقریبی هم ارزش دارد** — لازم نیست دقیق
باشد.

## جایی که واقعاً می‌درخشد

- **جبران گرانش** در بازوی رباتیک: $u_{FF} = mgl\sin(\theta)$
- **جبران اصطکاک** در سروو: علامت سرعت ضرب در ثابت
- **نرخ خوراک** در فرایند: خوراک ورودی معلوم است، اثرش پیش‌بینی‌پذیر
- **جبران دمای محیط** در هیتر
