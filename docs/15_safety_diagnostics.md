# ۱۵ — ایمنی و عیب‌یابی

## ۱۵.۱ اعتبارسنجی سنسور

یک سنسور خراب می‌تواند حلقه را به محرک تمام‌باز برساند. PIDX می‌تواند
اندازه‌گیری را قبل از استفاده بررسی کند:

```c
cfg.safety.enabled          = true;
cfg.safety.meas_min         = -10.0f;    /* خارج از این = خطا */
cfg.safety.meas_max         = 150.0f;
cfg.safety.meas_rate_max    = 50.0f;     /* |dy/dt| غیرممکن = خطا */
cfg.safety.failsafe_output  = 0.0f;      /* خروجی در حالت خطا */
cfg.safety.fault_persist_n  = 3;         /* ۳ نمونهٔ بد پشت‌سرهم */
cfg.safety.auto_recover     = true;
```

**`meas_rate_max` مهم‌تر از آن است که به نظر می‌رسد.** یک ترموکوپل قطع‌شده
معمولاً عددی *داخل* محدودهٔ مجاز می‌دهد، ولی با پرشی که فیزیکاً ناممکن است.
نرخ، خرابی را زودتر از محدوده می‌گیرد.

**`fault_persist_n` از هشدار کاذب جلوگیری می‌کند.** یک نمونهٔ پرت به خاطر
نویز EMI نباید کل حلقه را قفل کند.

## ۱۵.۲ بازیابی بدون ضربه

وقتی `auto_recover` روشن است و سنسور برمی‌گردد، کنترلر باید از همان خروجی
fail-safe **ادامه** بدهد، نه اینکه بپرد.

این یکی از نه نقصی بود که در این کتابخانه پیدا و رفع شد: در پیش‌نویس اول،
حل معکوس انتگرال قبل از محاسبهٔ P و D انجام می‌شد، که یک پرش
**۰.۲۰ → ۰.۲۹** روی محرک می‌ساخت. حالا به مرحلهٔ ۱۰ موکول شده.

```c
if (!cfg.safety.auto_recover) {
    PID_ClearFault(&pid);   /* بازیابی دستی */
}
```

## ۱۵.۳ پرچم‌ها و وضعیت

```c
uint16_t flags = PID_GetFlags(&pid);
if (flags & PID_FLAG_SATURATED_HIGH) { /* محرک تمام‌باز */ }
if (flags & PID_FLAG_FAULT)          { /* در حالت خطا */ }
```

| پرچم | معنا |
|---|---|
| `PID_FLAG_SATURATED_HIGH` / `_LOW` | خروجی به حد رسیده |
| `PID_FLAG_INTEGRAL_ACTIVE` | انتگرال در حال انباشت |
| `PID_FLAG_INTEGRAL_LIMITED` | انتگرال محدود شد |
| `PID_FLAG_SENSOR_INVALID` | نمونهٔ فعلی رد شد |
| `PID_FLAG_FAULT` | خطا قفل شده |

## ۱۵.۴ خطای چسبان

```c
PID_StatusCode code;
PID_GetLastError(&pid, &code);   /* اولین خطا از آخرین پاک‌سازی */
PID_ClearError(&pid);
```

**«اولین» است نه «آخرین».** دلیلش این است که خطای اول معمولاً علت است و
بقیه معلول. اگر یک ورودی `NaN` بیاید، ده خطای بعدی همه پیامد همان‌اند.

## ۱۵.۵ Telemetry بدون قفل

یک حلقهٔ SPSC (تک‌تولیدکننده/تک‌مصرف‌کننده) که از ISR پر می‌شود و از حلقهٔ
اصلی خوانده می‌شود — **بدون قفل و بدون بخش بحرانی**:

```c
static PID_TelemetryRecord storage[64];
static PID_Telemetry tel;

PID_Telemetry_Init(&tel, storage, 64);
PID_Telemetry_Attach(&pid, &tel);

/* در حلقهٔ اصلی: */
PID_TelemetryRecord rec;
while (PID_Telemetry_Read(&tel, &rec) == PID_OK) {
    log_it(&rec);
}
```

**تصمیم طراحی:** وقتی حلقه پر است، **جدیدترین** رکورد دور ریخته می‌شود نه
قدیمی‌ترین. دلیلش این است که تولیدکننده (ISR) هرگز نباید `tail` را جلو
ببرد — آن کار به یک بخش بحرانی نیاز دارد و کل هدف «بدون قفل» را از بین
می‌برد.

اندازه‌گیری‌شده: ۳۶۹۰ + ۲۲۷۹ + ۳۱ = **۶۰۰۰** رکورد، بدون گم‌شدن حسابداری.

## ۱۵.۶ سنجه‌های تشخیصی

سنجه‌ها در یک شیء **جدا** نگه داشته می‌شوند، نه داخل `PID_Handle` — پس
اگر نمی‌خواهیدشان، حتی یک بایت رم هم نمی‌گیرند:

```c
static PID_LoopMetrics met;

PID_Metrics_Reset(&met);

/* هر نمونه، بعد از PID_Update: */
PID_Metrics_Update(&met, &pid);

float mae  = PID_Metrics_MeanAbsError(&met);
float duty = PID_Metrics_SaturationDuty(&met);    /* کسری از زمان در اشباع */
float osc  = PID_Metrics_OscillationRate(&met);   /* تغییر علامت بر ثانیه */
```

**`SaturationDuty` بهترین شاخص سلامت حلقه است.** اگر پیوسته بالای ۲۰٪ باشد،
محرکتان کوچک است یا setpoint دست‌نیافتنی — و هیچ تنظیمی این را درست نمی‌کند.

**`OscillationRate` برای تشخیص تنظیم بیش‌ازحد تهاجمی است.** نرخ بالای تغییر
علامت خطا یعنی حلقه دارد شکار می‌کند.

## ۱۵.۷ چیزی که این ماژول نیست

اینها **تشخیص** هستند، نه **ایمنی تأییدشده**. اگر سیستم شما SIL/IEC 61508
می‌خواهد، این کتابخانه گواهی‌نامه ندارد و ادعایش را هم نمی‌کند. یک watchdog
سخت‌افزاری و یک مسیر خاموشی مستقل، جایگزین‌ناپذیرند.
