# ۱۶ — محاسبات ممیز ثابت (Fixed-Point)

## چرا وجود دارد

Cortex-M0/M0+ و بخشی از M3ها **FPU ندارند**. روی این‌ها هر عمل `float` به
کتابخانهٔ نرم‌افزاری می‌رود: یک ضرب ممیز شناور که روی M4F یک سیکل است، روی
M0 حدود ۵۰ تا ۱۰۰ سیکل می‌شود.

`PIDq_*` یک کنترلر PID **کاملاً صحیح‌عدد** است. نه `float` در مسیر داغ، نه
`math.h`، نه تقسیم.

```c
#include "pidx/pid_fixed.h"
```

## قالب اعداد

| قالب | معنی | بازه |
|---|---|---|
| **Q15** | سیگنال‌ها (setpoint، اندازه‌گیری، خروجی) | $[-1, 1)$ |
| **Q16.16** | بهره‌ها | $[-32768, 32768)$ |

`PIDQ_ONE = 32768` نمایندهٔ ۱.۰ است، ولی بزرگ‌ترین عدد قابل‌نمایش
`PIDQ_MAX = 32767` است. این تفاوت یک‌واحدی، منبع کلاسیک باگ سرریز است و در
کتابخانه صریحاً مدیریت شده.

## مقیاس‌بندی: مهم‌ترین کاری که باید بکنید

Q15 یعنی همه‌چیز باید به بازهٔ $[-1, 1)$ نگاشت شود. اگر دمای شما
$0..200$ درجه است:

$$y_{Q15} = \frac{y_{^\circ C}}{200} \times 32768$$

```c
/* ADC ۱۲ بیتی که ۰..۲۰۰ درجه را پوشش می‌دهد */
int16_t y_q15 = (int16_t)(((int32_t)adc_raw * 32768) / 4096);
```

**اشتباه رایج:** مقیاس‌بندی نکردن و بعد تعجب از اینکه چرا خروجی همیشه اشباع
است.

## تبدیل ثابت‌ها در زمان کامپایل

```c
qcfg.kp_q16 = PIDQ_F_TO_Q16(2.5);    /* کامپایلر حساب می‌کند */
qcfg.ki_q16 = PIDQ_F_TO_Q16(0.75);
```

این ماکروها **تنها جایی هستند که `float` در این ماژول ظاهر می‌شود** و چون
عبارت ثابت است، کامپایلر آن را حل می‌کند و هیچ کد ممیز شناوری به تارگت
نمی‌رسد.

اگر toolchain شما اصلاً soft-float ندارد، عددها را روی PC حساب کنید و
مستقیم بنویسید.

## استفادهٔ کامل

```c
static PIDq_Handle qpid;

void control_init(void)
{
    PIDq_Config cfg;
    PIDq_ConfigDefault(&cfg);

    cfg.kp_q16 = PIDQ_F_TO_Q16(2.0);
    cfg.ki_q16 = PIDQ_F_TO_Q16(0.5);
    cfg.kd_q16 = PIDQ_F_TO_Q16(0.1);

    cfg.dt_us  = 1000;        /* ۱ کیلوهرتز، بر حسب میکروثانیه */
    cfg.tf_us  = 10000;       /* ثابت زمانی فیلتر مشتق */

    cfg.out_min_q15 = 0;
    cfg.out_max_q15 = PIDQ_MAX;

    cfg.aw_mode  = PIDQ_AW_BACK_CALC;
    cfg.bc_shift = 3;         /* ضریب = 2^-3 */
    cfg.lpf_shift = 4;        /* فیلتر ورودی EMA */

    PIDq_Init(&qpid, &cfg);
    PIDq_SetSetpoint(&qpid, PIDQ_F_TO_Q15(0.5));
}

void control_tick(void)       /* در ISR تایمر */
{
    int16_t y = read_adc_q15();
    int16_t u = PIDq_Update(&qpid, y);
    write_pwm(u);
}
```

## چرا `bc_shift` به‌جای یک ضریب دلخواه

ضریب back-calculation به توان‌های دو محدود شده تا تصحیح یک **شیفت** باشد نه
یک تقسیم. تقسیم صحیح روی M0 حدود ۳۰ سیکل است و کل هدف این ماژول را از بین
می‌برد.

`bc_shift` بین ۱ تا ۱۵. مقدار کوچک‌تر = تصحیح تندتر.

## اندازه‌گیری‌شده

| مسیر | ns/call (x86-64) | FLOPs |
|---|---|---|
| `PID_UpdateFast` (float) | ~۲.۹ – ۳.۰ | ۱۲ |
| `PIDq_Update` (Q15) | ~۷.۰ – ۷.۷ | **۰** |

> ⚠️ **روی x86-64 نسخهٔ صحیح‌عدد کندتر است** — چون این پردازنده FPU بسیار
> سریعی دارد. این عدد را به تارگت تعمیم ندهید. روی M0 که FPU ندارد نسبت
> **کاملاً برعکس** می‌شود.
>
> این دقیقاً همان دلیلی است که `bench/bench_dwt.c` وجود دارد: تنها راه
> دانستن، اندازه‌گیری روی سخت‌افزار خودتان است. ما عدد Cortex-M نمی‌سازیم.

اندازهٔ ساختار: `PIDq_Handle` = **۸۰ بایت** (در برابر ۳۴۴ بایت برای
`PID_Handle`).

`pid_fixed.c` = **۲۱۰۷ بایت** `.text` روی x86-64 با `-Os`.

## خودآزمایی

```c
if (!PIDq_SelfTest()) {
    /* حساب ممیز ثابت روی این پلتفرم درست کار نمی‌کند */
}
```

`PIDq_SelfTest()` چند بردار آزمون شناخته‌شده را اجرا می‌کند: گرد کردن،
اشباع، و رفتار شیفت علامت‌دار. روی پلتفرم‌هایی که شیفت راست عدد منفی را
منطقی (نه حسابی) انجام می‌دهند، شکست می‌خورد — و بهتر است زود بفهمید.

## محدودیت‌های صادقانه

**دقت.** Q15 حدود ۴.۵ رقم اعشار دارد. برای یک حلقهٔ کنترل معمولی کافی است،
برای یک ابزار اندازه‌گیری دقیق نه.

**بازهٔ دینامیکی.** اگر سیگنال شما هم مقادیر خیلی کوچک و هم خیلی بزرگ دارد،
ممیز شناور انتخاب بهتری است.

**سرریز انتگرال‌گر.** انتگرال‌گر داخلی Q31 است تا فضای کافی داشته باشد، ولی
با بهره‌های خیلی بزرگ و خطای پیوسته، باز هم می‌تواند به حد برسد. حدهای
`i_min_q15`/`i_max_q15` را ست کنید.

**این ماژول مستقل است.** `PIDq_*` از `PID_*` استفاده نمی‌کند و بالعکس. اگر
فقط نسخهٔ صحیح‌عدد را می‌خواهید، بقیهٔ کتابخانه را می‌توانید کامپایل نکنید.

۴۲ assertion این ماژول را پوشش می‌دهند.
