# ۲۲ — انحرافات MISRA-C:2012

PIDX با MISRA-C:2012 **همسو** است، نه گواهی‌شده. این تفاوت مهم است: ما ابزار
گواهی‌سازی تجاری اجرا نکرده‌ایم. آنچه داریم:

- C99 خالص، بدون افزونهٔ کامپایلر در هستهٔ کتابخانه
- بدون تخصیص پویا
- بدون بازگشت (recursion)
- بدون تابع با آرگومان متغیر در هسته
- gate هشدار: `-Wall -Wextra -Wconversion -Wdouble-promotion -Wshadow
  -Wcast-qual -pedantic -Werror` روی **۸۸ کامپایل** با صفر هشدار

هر انحراف آگاهانه اینجا فهرست شده.

---

## D-1 — Rule 11.4/11.5: تبدیل اشاره‌گر به عدد صحیح

**کجا:** `platform/stm32/pid_stm32.c` و `bench/bench_dwt.c`

```c
#define BENCH_DWT_CYCCNT (*(volatile uint32_t *)0xE0001004UL)
```

**چرا:** دسترسی به رجیستر سخت‌افزاری راه دیگری ندارد. این ذات برنامه‌نویسی
embedded است.

**کنترل جبرانی:** فقط در لایهٔ پلتفرم، که **اختیاری** است و هستهٔ کتابخانه
از آن استفاده نمی‌کند. آدرس‌ها معماری‌اند و از مستندات ARM آمده‌اند.

---

## D-2 — Rule 21.6: توابع I/O استاندارد

**کجا:** `examples/`, `tests/`, `sim/`, `bench/`

**چرا:** `printf` برای نمایش نتیجه به کاربر.

**کنترل جبرانی:** **هیچ‌کدام در `src/` نیستند.** کتابخانه هرگز چاپ نمی‌کند.
`grep printf src/` خالی است.

---

## D-3 — Directive 4.9: ماکروهای شبه‌تابع

**کجا:** `PIDQ_F_TO_Q15()`, `PIDQ_F_TO_Q16()` در `pid_fixed.h`

**چرا:** باید در زمان **کامپایل** ارزیابی شوند تا هیچ کد ممیز شناوری به
تارگت بدون FPU نرسد. یک `static inline` این تضمین را نمی‌دهد.

**کنترل جبرانی:** آرگومان دقیقاً یک بار استفاده نمی‌شود ولی ماکرو فقط برای
عبارت‌های **ثابت** مستند شده. تست `test_fixed` صحت مقادیر را بررسی می‌کند.

---

## D-4 — Rule 15.5: چند نقطهٔ خروج از تابع

**کجا:** در سراسر کتابخانه، مثلاً `if (h == NULL) { return PID_ERR_NULL; }`

**چرا:** بازگشت زودهنگام برای اعتبارسنجی آرگومان، کد را **خواناتر** و
تودرتویی را کمتر می‌کند. جایگزینش یک زنجیرهٔ عمیق `if/else` است که
احتمال خطای انسانی را بالا می‌برد.

**کنترل جبرانی:** بازگشت‌های زودهنگام فقط در ابتدای تابع و فقط برای
اعتبارسنجی‌اند. هیچ تابعی وسط منطق اصلی خروج زودهنگام ندارد.

---

## D-5 — Rule 19.2: type punning با `union`

**کجا:** `include/pidx/pid_math.h` — توابع طبقه‌بندی ممیز شناور

```c
union { float f; uint32_t u; } v;
```

**چرا:** تشخیص `NaN`/`Inf` **بدون** `libm` و بدون نقض strict aliasing، راه
دیگری ندارد. استفاده از `isnan()` یعنی وابستگی به `math.h` در مسیر داغ، و
`x != x` را کامپایلر با `-ffast-math` حذف می‌کند.

**کنترل جبرانی:** type punning از طریق `union` در C99 صریحاً
**تعریف‌شده** است (بند ۶.۵.۲.۳p3، پانویس ۸۲) و GCC/Clang/ARMCC پشتیبانی
می‌کنند. این انحراف در خود `pid_math.h` هم مستند شده.

---

## D-9 — Rule 15.1: استفاده از `goto`

**کجا:** یک مورد، `src/pid.c` خط ۵۴۸ — پرش به برچسب `diag:`

```c
#if PIDX_ENABLE_DIAGNOSTICS
    goto diag;
#else
    if (err != NULL) { *err = rc; }
    return u;
#endif
```

**چرا:** مسیر خروجِ حالت MANUAL باید همان بلوک ثبت تشخیص انتهای تابع را
اجرا کند. جایگزین‌ها بدتر بودند: یا تکرار کل بلوک تشخیص (احتمال واگرایی
دو نسخه)، یا یک پرچم و یک `if` اضافه در مسیر داغ.

**کنترل جبرانی:** پرش **رو به جلو** است، از تابع خارج نمی‌شود، و از هیچ
مقداردهی اولیه‌ای عبور نمی‌کند — یعنی همان محدودیت‌هایی که MISRA در
Rule 15.2/15.3 می‌گذارد رعایت شده. فقط وقتی کامپایل می‌شود که تشخیص فعال
باشد.

---

## D-6 — Rule 8.9: متغیر با دامنهٔ فایل

**کجا:** جداول ثابت در `pid_autotune_rules.c`

**چرا:** جدول ضرایب قوانین تنظیم باید `static const` باشد تا در Flash بماند.

**کنترل جبرانی:** همه `const` هستند و هیچ حالت قابل‌تغییری در سطح فایل وجود
ندارد. **کتابخانه هیچ متغیر سراسری قابل‌نوشتن ندارد** — که یعنی چند نمونهٔ
کنترلر کاملاً مستقل‌اند.

---

## D-7 — Rule 10.x: تبدیل ضمنی

**کجا:** تبدیل‌های `float`↔`int` در ماژول fixed-point.

**چرا:** ذات تبدیل قالب عددی.

**کنترل جبرانی:** همهٔ تبدیل‌ها **صریح** (`(int32_t)x`) هستند و
`-Wconversion -Werror` تضمین می‌کند هیچ تبدیل ضمنی از قلم نیفتاده.

---

## D-8 — Directive 4.12: تخصیص پویا

**رعایت شده، انحراف ندارد.** `grep -E "\b(malloc|calloc|realloc|free)\b" src/`
خالی است. تمام حافظه مال کاربر است.

---

## آنچه گواهی نمی‌کنیم

- **گواهی‌نامهٔ رسمی MISRA** نداریم. ابزار تجاری (PC-lint، Polyspace،
  Coverity) اجرا نشده.
- **IEC 61508 / ISO 26262 / DO-178C** — هیچ‌کدام. اگر پروژهٔ شما اینها را
  لازم دارد، این کتابخانه به‌تنهایی کافی نیست.
- **تحلیل ایستای کامل** — فقط هشدارهای GCC.

اگر ابزار گواهی‌سازی دارید و اجرا کردید، نتیجه‌اش برای ما ارزشمند است.
