# ۱۲ — Gain Scheduling

## چرا لازم است

یک مجموعه بهرهٔ ثابت فقط در یک نقطهٔ کار بهینه است. فرایندهای واقعی غیرخطی‌اند:

- بهرهٔ یک شیر با درصد بازشدگی عوض می‌شود.
- ثابت زمانی یک مخزن با سطح مایع عوض می‌شود.
- اینرسی یک بازوی رباتیک با موقعیت عوض می‌شود.

Gain scheduling یعنی **چند مجموعه بهره** که بر اساس یک متغیر قابل‌اندازه‌گیری
انتخاب می‌شوند.

## استفاده

```c
#include "pidx/pid_gainsched.h"

/* جدول در Flash می‌ماند: کپی نمی‌شود، فقط ارجاع داده می‌شود.
 * باید بر حسب x صعودی مرتب باشد و حداقل ۲ نقطه داشته باشد. */
static const PID_GainPoint points[] = {
    /*   x     kp     ki     kd   */
    {   0.0f, 1.0f, 0.10f, 0.00f },
    {  50.0f, 2.0f, 0.30f, 0.05f },
    { 100.0f, 4.0f, 0.80f, 0.10f }
};

static PID_GainSchedule sched;

PID_GainSched_Init(&sched, points, 3,
                   PID_SCHED_SRC_MEASUREMENT,   /* چه چیزی جدول را می‌راند */
                   PID_SCHED_INTERP_LINEAR);
PID_GainSched_SetHysteresis(&sched, 2.0f);
PID_GainSched_Attach(&pid, &sched);
```

اگر منبع را `PID_SCHED_SRC_EXTERNAL` بگذارید، متغیر را خودتان می‌دهید:

```c
PID_GainSched_SetVar(&pid, tank_level);   /* هر نمونه */
```

## شش منبع زمان‌بندی

| منبع | متغیر |
|---|---|
| `PID_SCHED_SRC_SETPOINT` | setpoint مؤثر (بعد از shaper) |
| `PID_SCHED_SRC_MEASUREMENT` | اندازه‌گیری فیلترشده |
| `PID_SCHED_SRC_ERROR` | خطای علامت‌دار |
| `PID_SCHED_SRC_ABS_ERROR` | ǀخطاǀ — «بهره بر حسب فاصله» |
| `PID_SCHED_SRC_OUTPUT` | خروجی قبلی — اقتدار محرک |
| `PID_SCHED_SRC_EXTERNAL` | هرچه خودتان بدهید |

## سه حالت درون‌یابی

| حالت | رفتار |
|---|---|
| `PID_SCHED_INTERP_LINEAR` | درون‌یابی خطی، پیوستهٔ $C^0$ — ارزان‌ترین |
| `PID_SCHED_INTERP_SMOOTH` | smoothstep، پیوستهٔ $C^1$ — نرم‌ترین |
| `PID_SCHED_INTERP_HOLD` | پله‌ای؛ فقط جایی که پرش بهره اشکالی ندارد |

## Hysteresis: چرا لازم است

اگر متغیر زمان‌بندی دقیقاً روی مرز بین دو ناحیه نوسان کند، بهره‌ها هم نوسان
می‌کنند و حلقه ناپایدار به نظر می‌رسد.

`PID_GainSched_SetHysteresis(&sched, 2.0f)` یعنی برای عوض کردن ناحیه، متغیر باید ۲ واحد از مرز رد شود.

## چرا این ذاتاً bumpless است

چون انتگرال‌گر PIDX در **واحد خروجی** ذخیره می‌شود (§۰۳)، تغییر $K_i$ مقدار
انباشته را دست نمی‌زند. پس عوض شدن بهره‌ها — چه دستی چه از طریق scheduling —
خروجی را نمی‌پراند.

اگر انتگرال خام ذخیره می‌شد، هر تغییر بهره یک ضربه روی محرک بود.

## محدودیت صادقانه

Gain scheduling **کنترل تطبیقی نیست**. جدول را شما می‌سازید و کتابخانه فقط
درون‌یابی می‌کند. اگر مدل غیرخطی‌تان را نمی‌شناسید، این کمکی نمی‌کند.

برای تنظیم مجدد نظارت‌شده، `PID_AutoTune_Retune()` را ببینید (§۱۴).
