# ۱۳ — کنترل آبشاری (Cascade)

## ایده

یک حلقه، دو مسئله را با هم حل نمی‌کند: اگر اغتشاش در **درون** فرایند وارد
شود (مثلاً افت فشار خط در یک شیر)، حلقهٔ بیرونی تا وقتی اثرش به خروجی نرسد
خبردار نمی‌شود — و آن موقع دیر است.

Cascade یک حلقهٔ **درونی سریع** اضافه می‌کند که آن اغتشاش را قبل از اینکه به
خروجی برسد می‌گیرد:

```
SP ──► [PID بیرونی] ──► SP درونی ──► [PID درونی] ──► محرک ──► فرایند
             ▲                              ▲                    │
             │                              └── سنسور سریع ◄─────┤
             └────────────────── سنسور کند ◄──────────────────────┘
```

مثال کلاسیک: کنترل دما (کند، بیرونی) که setpoint یک حلقهٔ کنترل جریان
(سریع، درونی) را می‌دهد.

## اندازه‌گیری‌شده

از `tests/test_cascade` — دفع همان اغتشاش:

| ساختار | انحراف |
|---|---|
| تک‌حلقه | ۰.۰۵۲۸۹ |
| Cascade | **۰.۰۰۶۲۸** |

**۸.۴ برابر بهتر.** این بزرگ‌ترین بهبود تک‌قابلیتی در کل این کتابخانه است.

## قاعدهٔ طلایی

**حلقهٔ درونی باید حداقل ۳ تا ۵ برابر سریع‌تر از بیرونی باشد.** اگر نباشد،
دو حلقه با هم تداخل می‌کنند و نتیجه از تک‌حلقه بدتر می‌شود.

## استفاده

```c
#include "pidx/pid_cascade.h"

static PID_Handle outer, inner;
static PID_Handle *loops[2] = { &outer, &inner };   /* بیرونی → درونی */
static PID_Cascade casc;

PID_Cascade_Init(&casc, loops, 2);

/* حلقهٔ درونی هر نمونه، بیرونی هر ۱۰ نمونه اجرا شود.
 * محدودهٔ setpoint که حلقهٔ بیرونی مجاز است به درونی بدهد: */
PID_Cascade_ConfigLevel(&casc, 0, 10, -5.0f, 5.0f);   /* بیرونی */
PID_Cascade_ConfigLevel(&casc, 1,  1, -1.0f, 1.0f);   /* درونی  */

PID_Cascade_SetAntiWindup(&casc, PID_CASCADE_AW_FREEZE, 0.0f);

/* هر تیک: */
PID_Float meas[2] = { temp_c, flow_lpm };
float u = PID_Cascade_Update(&casc, meas, setpoint, dt);
```

ترتیب اجرا بیرونی→درونی است، خروجی هر سطح (بعد از clamp) setpoint سطح بعدی
می‌شود، و اشباع **در همان فراخوانی** به بیرون برگردانده می‌شود — نه یک نمونه
دیرتر.

## Anti-windup در cascade

وقتی حلقهٔ درونی اشباع است، حلقهٔ بیرونی هیچ اقتدار واقعی ندارد. اگر خبردار
نشود، windup می‌کند.

اندازه‌گیری‌شده:

| حالت | اورشوت | پیک ǀIǀ |
|---|---|---|
| `PID_CASCADE_AW_NONE` | ۳۵.۹۹٪ | ۱.۶۲۸ |
| `PID_CASCADE_AW_BACK_CALC` | ۲۵.۹۳٪ | ۱.۱۵۳ |
| `PID_CASCADE_AW_FREEZE` | **۱۷.۶۵٪** | **۰.۷۷۳** |

**در cascade، `FREEZE` از `BACK_CALC` بهتر بود** — برخلاف حلقهٔ تکی که
back-calculation برنده است (§۰۸).

علتش: حلقهٔ بیرونی وقتی درونی اشباع است هیچ اقتداری ندارد، پس عقب‌کشیدن
*تدریجی* انتگرال هنوز اجازه می‌دهد مقداری windup بماند. فریز کردن کامل،
درست‌ترین کار است.

## نکات عملی

**Decimation:** حلقهٔ بیرونی لازم نیست هر نمونه اجرا شود. با `decimation=10`
هر ۱۰ فراخوانی یک بار اجرا می‌شود — هم CPU کمتر، هم جدایی نرخ‌ها را تضمین
می‌کند.

**محدودهٔ setpoint درونی:** `sp_min`/`sp_max` در `PID_Cascade_ConfigLevel`
یک محافظ ایمنی واقعی است. حلقهٔ بیرونی نباید بتواند به درونی یک فرمان
غیرممکن بدهد.

**حالت‌ها هماهنگ عوض می‌شوند:** `PID_Cascade_SetMode()` هر دو حلقه را با هم
و بدون ضربه جابه‌جا می‌کند. (یکی از نه نقص پیداشده این بود که back-propagation
حالت‌های MANUAL/HOLD را نادیده می‌گرفت — رفع شد.)

**بیش از دو سطح:** پشتیبانی می‌شود، ولی به‌ندرت ارزش دارد. سه سطح یعنی سه
سنسور و سه برابر پیچیدگی راه‌اندازی.
