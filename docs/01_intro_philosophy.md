# ۰۱ — معرفی و فلسفهٔ طراحی

## PIDX چیست

یک کتابخانهٔ کنترل PID به زبان **C99** برای میکروکنترلرها — با تمرکز اصلی روی
STM32، ولی بدون هیچ وابستگی به آن. همان کد روی ARM Cortex-M، ESP32، و PC/Linux
کامپایل و اجرا می‌شود.

هدف این است که یک API پنج‌خطی برای کسی که تازه شروع کرده کافی باشد، و همان
کتابخانه تا یک فریم‌ورک کنترل کامل (cascade، gain scheduling، auto-tuning،
fixed-point) بالا برود — **بدون اینکه کاربر سادهٔ اول، هزینهٔ قابلیت‌های
پیشرفته را بپردازد.**

```c
/* کل چیزی که برای شروع لازم است */
PID_Handle pid;
PID_InitDefault(&pid);                      /* پیش‌فرض‌های امن، بهره‌ها صفر */
PID_SetGains(&pid, 2.0f, 0.5f, 0.1f);       /* Kp, Ki, Kd */
PID_SetOutputLimits(&pid, 0.0f, 100.0f);
PID_SetSetpoint(&pid, 60.0f);
for (;;) { actuate(PID_Update(&pid, read_sensor())); }
```

> بهره‌ها عمداً از صفر شروع می‌شوند: تا وقتی `PID_SetGains()` را صدا نزنید،
> کنترلر خروجی صفر می‌دهد. یک نقطهٔ شروع **بی‌اثر و امن**.

---

## هفت اصلی که همه‌چیز از آن‌ها می‌آید

### ۱. بدون تخصیص پویا

هیچ `malloc`، `calloc`، `realloc` یا `free` در کل کتابخانه نیست. تمام حافظه
یا static است یا مال خود کاربر:

```c
static PID_Handle pid;      /* شما مالک آن هستید */
```

چرا؟ چون روی یک سیستم embedded که ماه‌ها بی‌وقفه کار می‌کند، fragmentation یک
احتمال نیست، یک **قطعیت با تأخیر** است. علاوه بر این، `PID_Handle` را می‌شود
در قسمت خاصی از حافظه (`CCMRAM`، `DTCM`) گذاشت که روی STM32 تفاوت سرعت واقعی
دارد.

### ۲. هستهٔ کنترل هیچ چیز از سخت‌افزار نمی‌داند

در `src/pid.c` نه `#include "stm32f4xx_hal.h"` هست و نه `HAL_GetTick()`.
زمان را **شما** می‌دهید:

```c
float u = PID_UpdateDt(&pid, y, dt_seconds);
```

اگر لایهٔ پلتفرم را می‌خواهید، جداگانه و **اختیاری** است:
`platform/stm32/` و `platform/posix/`. این یعنی هستهٔ کنترل را می‌شود روی PC
تست کرد — و ۷۵۲ assertion این کتابخانه دقیقاً به همین دلیل وجود دارند.

### ۳. قابلیت خاموش = صفر هزینه

هر قابلیت اختیاری با یک ماکرو در زمان کامپایل حذف می‌شود. «حذف» یعنی واقعاً
صفر: نه فلش، نه رم، نه یک شاخهٔ `if` در زمان اجرا.

| پروفایل | Flash (x86-64, `-Os`) |
|---|---|
| `MINIMAL` | ۷٬۷۹۲ B |
| `MOTION` | ۱۶٬۶۳۳ B |
| `PROCESS` | ۲۱٬۰۰۱ B |
| `FULL` | ۲۵٬۳۹۹ B |

اینها با `bench/size_report.sh` اندازه‌گیری شده‌اند، نه تخمین. (اعداد x86-64
هستند؛ روی Thumb-2 معمولاً کمتر است — §۱۷.)

### ۴. الگوریتم‌های واقعی، بدون stub

هیچ قابلیتی که نتواند از نظر ریاضی درست پیاده شود وارد کتابخانه نمی‌شود. در
کل پروژه یک `TODO` هم نیست. Auto-tuning یک ماشین حالت واقعی است با شناسایی
relay و step؛ fixed-point واقعاً Q15/Q31 است؛ cascade واقعاً back-propagation
اشباع دارد.

جای اینکه ادعا کنیم «کار می‌کند»، **اندازه‌اش گرفته‌ایم** — و وقتی نتیجه بد
بوده، همان بد را منتشر کرده‌ایم (§۵ پایین).

### ۵. مسیر داغ بدون تقسیم

`PID_Update` هیچ تقسیمی و هیچ فراخوانی `math.h` ندارد. تمام ضرایب یک بار در
`pidp_recompute()` تا می‌شوند و بعد فقط ضرب و جمع می‌ماند.

| مسیر | ns/call (x86-64) | نسبت |
|---|---|---|
| `PID_UpdateFast` | ~۲.۹۵ | ۱.۰۰× |
| `PID_Update` | ~۱۲.۱ | ~۴.۱× |
| `PID_UpdateDt` (dt ثابت) | ~۱۲.۲ | ~۴.۱× |
| `PID_UpdateDt` (dt متغیر) | ~۱۶.۷ | ~۵.۷× |

### ۶. MISRA-C:2012 با انحرافات مستند

هر جا از قاعده‌ای عبور کرده‌ایم، در `docs/22_misra_deviations.md` نوشته شده
که کجا، چرا، و چه چیزی به جایش تضمین می‌شود.

### ۷. کامنت انگلیسی، مستند فارسی

کامنت‌های کد انگلیسی‌اند (چون کد ممکن است دست هر کسی برسد)، مستندات فارسی
است، و نام‌های API انگلیسی می‌مانند.

## چیزی که این کتابخانه را متفاوت می‌کند: نتایج بد را هم منتشر می‌کنیم

بیشتر کتابخانه‌های PID فهرست قابلیت دارند. ما **اندازه‌گیری** داریم — و
چند تا از آن اندازه‌گیری‌ها خوشایند نبودند. همه‌شان مانده‌اند:

**قانون `NO_OVERSHOOT` واقعاً اورشوت می‌دهد.** روی مدل کاملاً دقیق،
۴۲–۴۳٪ اورشوت. نام قانون از جدول دههٔ ۱۹۴۰ آمده و یک **قرارداد نیست**.
(§۱۴ و §۹.۱۰.۲ سند معماری.)

**کارایی روی مدل دقیق، مقاومت را وارونه پیش‌بینی می‌کند.** در ۸۱۰ اجرای
شبیه‌سازی، همبستگی رتبه‌ای بین «رتبهٔ IAE روی مدل دقیق» و «رتبهٔ بقا وقتی مدل
غلط است» برابر **ρ = −۰.۵۸۶** بود. Ziegler-Nichols که اول بود، هفتم شد؛
IMC که آخر بود، اول شد.

**تست relay همیشه `Ku` را کم تخمین می‌زند** — حتی با نویز صفر، تا −۲۵٪. علتش
را پیدا کردیم (هارمونیک‌های چرخهٔ حدی) و نگهش داشتیم، چون خطا در **جهت امن**
است.

**Slew limiting روی یک سروو ۱ کیلوهرتز، نتیجه را بدتر کرد.** در مثال مربوطه
نوشته شده که بدتر شد.

اگر جایی از این مستندات عددی می‌بینید، یا از یک اجرای واقعی آمده یا صریحاً
«هدف طراحی» برچسب خورده است. **هیچ عدد Cortex-M ساختگی در این مستندات نیست**
چون در محیط توسعه `arm-none-eabi-gcc` نصب نبود — به جایش `bench/bench_dwt.c`
را داریم که خودتان روی برد اجرا می‌کنید.

---

## این کتابخانه برای چه کسی نیست

- اگر یک PID سه‌خطی می‌خواهید و هیچ‌وقت بیشتر نمی‌خواهید، ۲۰ خط خودتان
  بنویسید کافی است.
- اگر MATLAB/Simulink code generation دارید و راضی هستید، این جایگزینش نیست.
- اگر به کنترل چندمتغیره (MIMO)، MPC یا کنترل تطبیقی کامل نیاز دارید، PIDX
  این‌ها را ندارد و ادعایش را هم نمی‌کند.
